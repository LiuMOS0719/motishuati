# 墨题 — ISTQB CTFL 刷题站

把 4 套官方模拟卷的 PDF 解析成题库、做成能按来源/题量/乱序练习的刷题站，以"过 ISTQB 考试"为目标组织：**主页选题量/来源/方式 → 一场一场地练 → 每场出分 + 错题明细 + AI 评价 → 历史留档**。

## 项目简介

| 项 | 说明 |
|---|---|
| 形态 | 单容器自托管 Web 应用，NAS 上常驻内存约 **15 MB**，镜像 149 MB |
| 技术栈 | **零第三方依赖**：Python 标准库 `http.server` + `sqlite3`；前端原生 JS，无框架、无构建步骤 |
| 代码量 | 约 4.5k 行（Python ~1.3k，前端 JS/CSS/HTML ~3.2k） |
| AI | DeepSeek / 智谱 GLM 双模型；答疑、整场评价、提问相关性判断、图片转写 |
| 主要功能 | 分场练习、选项乱序（解析字母同步重映射）、错题本、历史成绩、排行榜、管理员额度管理、题目纠错反馈 |

几个实现上的点：

- **按答案表切题**：PDF 提取的文本没有可靠题号边界，改用官方答案表驱动的题号定位，避免整卷错位
- **AI 计费按「场次 + 题目」记账**：同一场同一题追问不重复扣次，换场次重新计次（`ask_usage` 复合主键）
- **对话隔离**：AI 对话按「场次 + 题」存储，新一场练习从空白上下文开始
- **弱网优化**：首屏只传题目索引，正文按需分片加载；登录后 4 个接口并行；二次打开 20 秒内零请求
- **AI 输出安全**：先转义再渲染的轻量 markdown，防止模型输出里的标签被执行

## 快速开始（自带 3 道示例题）

```bash
git clone <仓库地址> motishuati && cd motishuati
cp .env.ai.example .env.ai          # 填自己的 DeepSeek / 智谱 key；不填则 AI 功能关闭
docker build -t moti:1 .
docker run -d --name moti -p 8090:8090 \
  -v "$PWD/data:/data" --env-file .env.ai moti:1
```

浏览器打开 `http://localhost:8090`，注册账号即可（第一个注册的账号自动成为管理员）。

仓库里没有 ISTQB 官方模拟卷的题目正文和图片，只有 `data/questions.sample.json` 的 3 道示例题；要换成自己的题库，按下文「题库」的字段格式放 `data/questions.json`（存在时优先使用）并重启容器。

## 访问与账号

- 线上：`https://shuati.liumos.top`（nginx 反代到容器的 8090，证书自动续期）
- 本机：`http://<主机地址>:8090`
- 打开后先登录/注册：**「注册新账号」** 用户名 2–20 位（中英文、数字、下划线），密码 ≥6 位
- 同一个账号在手机、电脑登录都是同一份进度（数据存在服务器）
- 容器名 `moti`，飞牛「Docker」界面可直接启停

### 账号是怎么做的

| 项 | 实现 |
|---|---|
| 密码 | PBKDF2-HMAC-SHA256 + 每用户随机盐，20 万次迭代，库里只存哈希 |
| 登录态 | 随机 48 位十六进制 token，存在浏览器 localStorage，服务端库里有记录，**30 天过期** |
| 鉴权方式 | 请求头 `X-Auth-Token` |
| 数据表 | `users` / `auth_tokens` / `user_state`（每账号一行 JSON：场次 + 每题对话 + 进行中的练习） |
| 旧数据迁移 | 账号里还没有数据、而本机浏览器里有旧的历史时，**首次登录会自动把本机历史搬进账号**（不会被清空） |
| 关闭注册 | 需要的话可以在 `server.py` 的 `register()` 里限制用户名字符集或直接禁用该接口 |

### 权限与管理员

- `users.is_admin=1` 才是管理员；页头「⚙ 用户管理」按钮只有管理员看得到
- 系统会自动保证至少有一个管理员：优先 `liumos`，没有就取最早注册的那个
- 管理员能做的（`⚙ 用户管理` 弹窗里）：
  - 看每个用户的 deepseek 剩余次数、已用题数、提问总次数、**同一题最多问了多少次（标出是哪道题，如 `7 次（C-32）`）**、作答题数
  - 还会列出「提问最多的题」前 5：`C-32×7、A-7×3(GLM)、D-14×2…`
  - 对任意用户 `−5 / −1 / +1 / +5 / 重置 50`

### AI 模型与次数

| 模型 | 计次规则 | 默认额度 |
|---|---|---|
| **GLM（glm-4-flash）— 默认** | 不限次数 | — |
| DeepSeek | **按「场次 + 题」计次**：同一场练习的同一道题第一次提问扣 1 次，本场本题的后续追问不扣；开始新一场练习后再问同一题，重新扣 1 次 | **新账号 0 次**，由管理员在「⚙ 用户管理」里按需发放 |

> 公网部署默认不给新注册账号 DeepSeek 额度：DeepSeek 按 token 计费，开放注册 + 送额度等于对外开放付费接口。新用户仍可用 GLM（免费档）答疑，需要 DeepSeek 时由管理员加次数。

> 登录失败计数按**真实来源 IP** 记（反代后从 `X-Real-IP` / `X-Forwarded-For` 取，且只在本机/内网来源时采信），避免所有人共用一个代理 IP 导致互相锁定。

**默认走 GLM**：答疑、整体评价、相关性与读图（glm-4.6v）全部默认用 GLM，只有你手动在抽屉里切到 DeepSeek 才消耗次数额度。

**相关性前置检查（三级，白名单优先，误杀优先避免）**

1. **命中强无关特征 → 直接拦**（不调模型，秒拦）：天气 / 几点 / 你是谁 / 写代码 / 帮我写 / 作文 / 讲个笑话 / 推荐网站 / 彩票 / 新闻…
2. **命中题目相关特征 → 直接放行**（不调模型，零延迟）：题 / 选项 / 答案 / 考点 / 解析 / 概念 / 例子 / 举例 / 场景 / 区别 / 记忆 / 怎么记 / 为什么 / 错在 / 正确 / 大纲 / 章节 / 翻译 / K1-K3 / 多选 / 单选…
3. **两边都不沾 → 交 GLM 判断，且 prompt 明确"拿不准一律 RELATED"**；模型调用失败也放行。

被拦时不消耗额度、不写入对话记录。实测：9 条原本会被误杀的提问（含站内快捷按钮「举一个具体的小例子」、「K1 和 K2 的区别」、「敏捷 vs Scrum 有什么区别」）**全部放行**；5 条闲聊/代写**全部拦住**；单次提问耗时从 3.4s 降到 1.4–1.8s（多数情况不再调判断模型）。

- 在「问 AI」抽屉顶部切换模型，按钮上实时显示 deepseek 剩余次数
- 次数用完后选 DeepSeek 会被拒（提示改用 GLM 或找管理员加次数），GLM 不受影响
- 每次回答下方会标「扣 1 次额度」还是「本场本题追问不计数」，并显示本次 token
- 用量记在 `ask_usage` 表（`user_id + session_id + qid + model` 唯一，`cnt` 是本场这题问了几次；老数据 `session_id` 为空串）
- **对话归属**：对话按「场次 + 题」隔离——同场同题保留上下文，换题换对话，**开始新一场练习后同一题从空白开始**，看不到以前场次的对话

### 主页左侧面板

- **用户信息**：做题次数、累计答题、正确率、答对/答错、DeepSeek 剩余次数、AI 提问总次数
- **用户排名**：默认按正确率排，可切「做题量」；自己那一行高亮

| 项 | 说明 |
|---|---|
| 题目来源 | **多选下拉**：点开是一个面板，分「按整卷」（完整卷名+发布日期，5 项）/「按章节」（第 1–6 章完整标题）/「错题本」（单选，与其它互斥，没错题时置灰）三组复选框，每项右侧标题数；收起时显示「全部题目（184 题）」或「已选 N 项 · X 题」 |
| 版权信息 | 多选框下方有「📄 查看所选题目的版权信息」（**未选来源时不显示**）；弹窗按所选来源列出各卷的正式名称、文档编号、版本、发布日期，并附 ISTQB®/CSTQB® 版权声明，注明仅供个人学习、不得商用 |
| 出题方式 | 顺序练习（按大纲顺序）/ 随机练习（洗牌） |
| 选项顺序 | **按原卷顺序** / **答案乱序**：乱序时每道题的 A/B/C/D 重新打乱（每场固定，刷新/继续不会变），官方解析里的 `a)` `b)` 等字母引用同步改写，AI 答疑也按新顺序回答 |
| 本次题量 | **下拉框**：10 / 20 / 30 / 40（默认）/ 60 / 80 / 100 题。**选的档位大于题池时按题池出**——例如来源只有 49 题、你选 60，下拉框仍显示 60（不会跳档），开始后实际出 49 题，提示里会写「只有 49 题，按 49 题出」 |
| 用户排名 | 按「已答正确率」或「做题量」排序。**数据缓存在浏览器**，点切换是本地即时渲染（实测 0.07 秒），同时后台请求最新榜单，回来后原地刷新；每 60 秒自动拉一次；刷新页面后也能立刻显示上次的榜单 |
| 章节掌握情况 | 6 行进度条，每章显示「已做/总题数 · 正确率」，点任一行动确认后直接开始练这一章 |
| 题目反馈 | 页头「⚠ 题目反馈」**仅管理员可见**；普通用户在答题页用「⚠ 题目有问题」提交单题反馈。徽标 = 待处理条数。提交时会记录提交人（`feedback.user_id / username`），接口层面管理员看全部、普通用户只能取到自己的。每条带 **👁 查看此题**（完整预览：题干 + 表格/SVG + 选项 + 正确答案高亮 + 解析），**✓ 已处理 / ✕ 忽略** 仅管理员可见。状态三态：待处理（黄）/ 已处理（绿）/ 已忽略（灰） |
| 历史做题情况 | 每次练习一条：正确率、来源、方式、题数、时间、答对数、是否已有 AI 评价；点进去看当场结果 |

各章题量（含附加题）：第 1 章 37、第 2 章 27、第 3 章 20、第 4 章 48、第 5 章 44、第 6 章 8。

- 正确率圆环 + 答对/答错数 + **按 40 题制折算的分数**（及格线 26 分；已答不足 15 题会标"样本太少"）
- **AI 评价**：基于本场作答给出总评、薄弱章节排序、复习动作、反复错误模式；可继续追问

## 数据存在哪

**答题记录、每题对话、整体评价都存在账号里（服务器 SQLite 的 `user_state` 表），按账号隔离。** 浏览器 localStorage 只是本地缓存，用于离线读写和加速，改动会防抖 700ms 推回服务器。

本地缓存会记一个 `moti_owner_v1`（缓存属于哪个账号）：**同一浏览器换账号时，旧的场次/对话/进行中练习会先被清掉**，不会被当成「本机历史」推到新账号（2026-11-25 修过一次串号 bug：新建账号继承了上一个账号的全部记录）。

| localStorage 键 | 内容 |
|---|---|
| `moti_token` | 登录 token（30 天有效） |
| `moti_sessions_v1` | 当前账号的历史场次缓存 |
| `moti_chats_v1` | 当前账号的 AI 对话缓存（键为 `场次id::题号`） |
| `moti_current_v1` | 正在进行的这场（未完成时换设备也能接着做） |
| `moti_owner_v1` | 本地缓存属于哪个账号（换账号时据此清空，防串号） |

清掉浏览器缓存不会丢数据——重新登录即可从服务器取回。要彻底删除某账号记录，见下面运维里的命令。

原 PDF 里的图题/表题，现在只截**图形本身**，不再给整页：

| 类型 | 题目 | 说明 |
|---|---|---|
| 位图（状态图、柱状图、依赖图） | A-23、B-23、C-23、C-31、C-32 | 按 PDF 里图片的真实 bbox 裁剪，含图前后 8pt 留白 |

表格题之所以要用图而不是文字：PDF 提取文本会丢掉列对齐（比如判定表的 T/F 落到哪一列完全看不出），一截图就还原了。
生成脚本在 `tools/ctfl_img2.py`（位图）和 `tools/ctfl_table_clip.py`（表格），换题库时改 `CLIPS` 配置即可重跑。

### 配图已全部改成代码渲染（不再用位图）

12 道配图题（7 张判定表/矩阵表 + 5 张状态图/柱状图/依赖图）现在由 `data/figures.json` 提供，存进 `figures` 表：

- **表格 → HTML `<table>`**：数据来自 PDF 里的文字坐标精确重建（每个 X/T/F 按 x 坐标归列），不是靠视觉模型猜，逐题核对过
- **图形 → 内联 SVG**：状态图/柱状图/依赖图按原图语义重绘，节点、连线、条件标签、数值与原图一致，配色跟随站点主题
- 体积：原来 12 张 WebP 位图约 686 KB → 现在约 **15 KB** 代码（−98%），且任意缩放不失真
- 手机端：表格横向滚动（`overflow-x:auto`，不会撑破页面），SVG 按容器宽度等比缩放
- AI 那边也受益：**表格类直接把表格数据转成文字喂给模型**（比位图转写精确），图形类仍用视觉模型的转写缓存

## 多题库架构（后续加 MySQL / Python 等）

站点名「墨题」，本身不绑定任何考试。题库是一个 `banks` 表里的记录，题目通过 `questions.bank_id` 归属到题库。

### 加一个新题库要做的事

1. 在 `data/banks.json` 里追加一条记录：

```json
{
  "id": "mysql",
  "name": "MySQL 数据库认证题库",
  "short": "MySQL",
  "subtitle": "MySQL 8.0 认证模拟题",
  "sort": 1,
  "ai_context": "你是 MySQL 认证考试的答疑老师……（这段会作为 AI 的 system 提示词）",
  "review_context": "你是 MySQL 备考教练……（整体评价用的提示词）",
  "chapters": [{"key": "1", "full": "第 1 章 架构与存储引擎"}],
  "papers": [{"key": "A", "label": "模拟卷 A", "copy_name": "……", "doc": "……", "ver": "……", "date": "……"}],
  "copyright_note": "题目来源说明……",
  "copyright": "版权声明全文……"
}
```

2. 准备题库数据 `questions.json`（每题需要 `id`、`bank_id`、`chapter`、`papers`、`no`、`stem`、`options`、`answer`、`explain` 等；`chapter` 可省略，会自动从 `lo` 字段的第一个数字推）
3. `docker exec moti python3 /app/import.py` 重新导入

导入后页头会出现题库切换下拉（只有 1 个题库时显示为灰色标签）。

### 哪些东西已经从硬编码改成读库

| 原来写死的 | 现在来自 |
|---|---|
| 卷名与发布日期（A/B/C/D） | `banks.papers[].label` |
| 章节标题（第 1–6 章） | `banks.chapters[].full` |
| 版权声明、出处说明 | `banks.copyright_note` / `banks.copyright` |
| AI 答疑的 system 提示词 | `banks.ai_context` |
| 整体评价的提示词 | `banks.review_context` |
| 题库名称/简称 | `banks.name` / `banks.short` |
| 题目归属章节 | `questions.chapter` |

新增题库时前端不用改任何代码。

## 安全与合规

| 项 | 做法 |
|---|---|
| 题库接口鉴权 | `/api/questions`、`/api/index` 必须带 `X-Auth-Token`，未登录返回 **401**（`/api/banks` 只含题库名与版权声明，保持公开） |
| 越权防护 | 答题数据按 `user_id` 隔离；管理员接口单独校验 `is_admin` |
| AI 生成标识 | 每条 AI 回答上方都带「AI 生成 · 仅供参考」角标（依据《人工智能生成合成内容标识办法》2025-09-01 施行） |
| AI 输出渲染 | 先 HTML 转义再做轻量 markdown 渲染（粗体/列表/小标题/代码），避免 AI 输出里的标签被执行 |
| AI 报错不甩原文 | 上游的 `HTTP 400: a` 这类原始报错只在服务端日志留档，前端按状态码翻译成可行动的提示：限流→「等几秒再问一次」、鉴权→「让管理员检查 API Key」、额度→「联系管理员充值或换模型」、超时/断网→「检查网络后再试」、空回答→「AI 这次没返回内容，请再问一次」 |
| 版权口径 | 弹窗写明“仅供个人学习、不得商用”，接口侧用登录校验与之对齐 |
| 禁止收录 | `GET /robots.txt` 返回 `Disallow: /`；所有响应带 `X-Robots-Tag: noindex, nofollow, noarchive`；HTML 内另有 `<meta name="robots">` 双保险 |
| 登录限流 | 同一 IP+用户名：**首轮允许错 8 次**，第 8 次错后锁 **60 秒**；解锁后**每轮只允许错 3 次**，且每再触发一次锁定，时长翻倍（60→120→240→480…，封顶 1 小时）。**登录成功立即清零**，下次又从 8 次起步。每次失败会告诉还剩几次；锁定期间请求直接返回 429 并倒计时。内存计数，重启归零 |
| DeepSeek 余额 | 管理员页头实时显示 `DeepSeek ¥53.06`（绿色；低于 5 元转红）。数据来自 DeepSeek 官方 `/user/balance` 接口，服务端缓存 5 分钟、浏览器也缓存 5 分钟；悬停看币种、充值余额、赠金与查询时间。接口 `/api/admin/deepseek-balance` 仅管理员可访问（非管理员与匿名均 403） |
| 图片题喂给 AI | 带配图的 12 道题，用视觉模型（glm-4.6v，失败回退 glm-4v-flash）把图转成 **markdown 表格 / 结构化文字**，按题目缓存在 `image_desc` 表，只算一次（`app/prewarm_images.py` 可批量预生成）。问答时把转写内容拼进上下文，纯文本模型也能“看到”图 |

## 分数口径

结果页的「按 40 题制折算」= **答对数 ÷ 本场总题数 × 40**，未答按 0 分计。
（不拿“已答题数”当分母——否则只答 1 题且答对就会显示 40 分，考试前最容易误判水平。）
已答不足 15 题时会标「仅供参考」。

## 数据自动更新（响应式 store + 自动同步）

前端没有用框架，但做了一层极简响应式（`js/util.js` 里的 `store`，约 15 行）：

```js
store.set('stats', s)      // 任何地方拿到新数据只需 set
store.bind('stats', ()=>{ renderUserCard(); renderRank(); updateQuotaUI(); })
```

绑定关系（一次绑定，全局生效，不再需要手写 render 调用）：

| 数据 | 自动触发渲染 |
|---|---|
| `stats` | 用户卡、排名、DeepSeek 配额 |
| `feedback` | 反馈列表、待处理徽标、计数 |
| `rank` | 排名列表 |
| `sessions` | 页头统计、历史列表、章节掌握 |

自动拉取策略：

- 练习提交 → `pushStateNow()` 立刻推送（不等 700ms 防抖），随后拉 stats
- 页面可见时每 **45 秒**自动拉 stats / 反馈 / 排名（管理员还含余额）
- **切回浏览器标签页**（`visibilitychange`）立即拉一次

这样两台设备同时开着，一边做完题，另一边最多 45 秒自己变，不用刷新。

## 前端文件结构与懒加载

> **改前端一定要同时 bump 版本号**：`index.html` 里的 `js/*.js?v=` 和 `css/app.css?v=` 都要跟着加，`util.js` 里的 `JS_VER` 也要改。否则浏览器会继续用缓存里的旧文件——2026-11-25 就踩过一次：新增弹窗的 CSS 没 bump，弹窗内容直接排在页面末尾。

单文件已拆开（原来 index.html 1838 行 / 87KB）：

```
static/
  index.html      283 行   骨架 + <link>/<script> 引用
  css/app.css     275 行   全部样式
  js/util.js      114 行   存储、$、esc、showPage、loadScript 等基础件
  js/quizcore.js  109 行   纯逻辑：选项乱序、字母重映射、来源/章节计算
  js/notes.js     148 行   问题记录本（管理员，页头按钮 + 弹窗）
  js/account.js   241 行   用户卡、排名（本地缓存）、DeepSeek 余额、管理弹窗、启动流程
  js/home.js      501 行   主页：来源多选、章节、历史、反馈、开练/续做
  js/auth.js       60 行   登录注册 + boot
  ── 以下按需懒加载（首次进入对应页面才下载）──
  js/quiz.js      135 行   答题页：题卡、判题、解析
  js/ai.js        209 行   AI 抽屉、markdown、反馈弹窗
  js/result.js    139 行   结果页、错题明细、整体评价
```

- 首屏只加载前 6 个（util / quizcore / notes / account / home / auth）+ css，其余用 `loadScript()` 动态注入，同一文件只请求一次
- 用 `defer` 保证执行顺序；JS/CSS 带 `?v=11` 查询串 + `max-age=3600` 长缓存（**改了 js/css 记得把版本号 +1，`JS_VER` 一起改**）
- 骨架 HTML 只有 `max-age=20, stale-while-revalidate=120`：20 秒内二次打开完全不发请求

## 性能数据（公网实测）

| 指标 | 拆分前 | 拆分后 |
|---|---|---|
| index.html | 87 KB（gzip 26 KB） | **10.5 KB（gzip 3.4 KB）** |
| 首屏 JS | 全在一个文件里 | 15 KB（gzip），另 22 KB 懒加载 |
| 登录后 API | 6 个**串行**（约 6×RTT） | login 后 index/me/state **并行**，再并行 stats/leaderboard |
| 二次打开 | 每次 304 往返 | **0 请求**（20 秒内走本地缓存） |

### 之前做过的弱网优化

| 措施 | 效果 |
|---|---|
| **gzip 压缩**（HTML / JSON，>800B 自动压） | 首页 63KB→**18KB**；题库索引 26KB→**2.4KB**；全量题库 288KB→73KB |
| **首屏懒加载**：只拉轻量索引 `/api/index`（不含题干/选项/答案/解析） | 首屏总传输从 ~351KB 降到 **约 21KB** |
| **题目正文按需加载**：进练习时才按场次批量拉 `?ids=` | 10 题 10.7KB、32 题 73KB；不再一次性拉 184 题 |
| **结果页按需加载**：点历史/结果时才拉那场的题干与解析 | 主页不背这个包袱 |
| **图片 WebP**（quality 90） | 11 张配图 686KB → **233KB**（−66%），且 `loading="lazy"` 只在滑到才下 |
| **图片长缓存** | `Cache-Control: public, max-age=2592000, immutable`，第二次访问不再下载 |
| **HTML / API 走 ETag** | 内容没变返回 **304**，几乎零流量；HTML 用 `no-cache` 保证能及时更新 |
| 加载占位 | 题目未到时显示「题目加载中…」，不会闪错乱 |

实测首屏请求只有两个：`/` 与 `/api/index`。

## API

| 接口 | 用途 |
|---|---|
| `POST /api/notes` | 管理员：问题记录本（`action` = list / add / set / del） |
| `POST /api/register` | `{username, password}` 注册，返回 token |
| `POST /api/login` | `{username, password}` 登录，返回 token |
| `POST /api/logout` | 注销当前 token |
| `GET /api/me` | 当前 token 对应的用户名 |
| `GET /api/state` / `PUT /api/state` | 拉取/推送该账号的场次+对话+进行中的练习（需 token） |
| `GET /api/questions` | 全量题目（含答案与解析，前端判题） |
| `POST /api/ask` | `{qid, question, answered, history[], model}` 单题答疑（deepseek/glm） |
| `GET /api/user/stats` | 当前用户的做题统计 + AI 用量 + 剩余额度 |
| `GET /api/leaderboard?sort=accuracy\|count` | 用户排名 |
| `GET /api/admin/users` | 管理员：所有用户的额度与用量 |
| `POST /api/admin/quota` | 管理员：`{username, delta}` 加减 deepseek 次数 |
| `POST /api/review` | `{stats, wrong[], chosen{}, history[]}` 本场整体评价 |
| `GET /api/health` | 题库数、AI 是否就绪、当前模型 |
| `POST /api/feedback` | `{qid, kind, note}` 记录题目问题 |
| `GET /api/feedback` | 题目反馈列表：管理员看到全部（最近 200 条），普通用户只看到自己的；未登录返回空 |

## 已知限制

- 账号是开放注册的（局域网内谁都能注册）；想限制可以改 `server.py` 的 `register()` 或直接去掉注册按钮的入口。
- 同一账号在两台设备同时答题时，以最后一次推送为准（后写覆盖，不做冲突合并）。
- 错题本的口径：历史场次里答错就进、之后答对则出。
- 其他电脑访问 8090 被拒属于飞牛网络策略，需在面板放行端口。
